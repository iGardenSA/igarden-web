## الفصل 8.5 — توسيع طبقة Tier 2 (جديد 17 مايو 2026)

### السياق

v3.0 أسّس لـ 3 طبقات لكن داخل Tier 2 جمهوران مختلفان:
- **المستثمرون والمُسرّعات** → Tier 2-A (وصول واسع للأرقام مع ضوابط)
- **الشركاء الداخليون تحت NDA** → Tier 2-B (وصول كامل تقريباً)

### التفريع الرسمي

| الطبقة الفرعية | الجمهور | ما يُسمح إضافة | ما يبقى محظوراً |
|---|---|---|---|
| **Tier 2-A** | Sunbulah, TASMU, Angels, VCs | Projections, Margins, Unit Economics, Funding Ask | أسماء العملاء، نسب الملكية، شراكات غير مؤكّدة |
| **Tier 2-B** | محامون، مدقّقون، Advisors NDA | أسماء العملاء + قيم العقود + تفاصيل الشراكات | نسب الملكية (إلا للمحامي/المدقق حصراً) |

### شروط Tier 2-A الإلزامية

1. كل projection مالي → disclaimer واضح (`subject to revision`)
2. كل ادعاء كمّي → **محسوب** (pipeline funnel أو market sizing أو unit economics)
3. الشراكات → تُذكر بدرجات (signed / active discussion / targeted)
4. كل رقم سوقي خارجي (TAM/SAM) → مصدر مذكور
5. أي وثيقة Tier 2-A → **مراجعة CEO قبل الإرسال الخارجي**

### الحالات الخاصة

- **Sunbulah/TASMU:** Tier 2-A مع التزام خاص بعدم الإيحاء باعتماد حكومي غير موجود
- **Demo days حيّ:** تتحوّل إلى Tier 0 حالما يدخل جمهور عام (مصوّرون، صحافة)
- **Board materials للمؤسسين الثلاثة:** Tier 3 — ليست Tier 2-A

## الفصل 19.4 — التزام HAL (Hardware Abstraction Layer)

كل تكامل عتاد جديد (Sensors, Relays, Controllers) يجب أن يمرّ عبر HAL:
- منع Vendor Lock-in
- مرونة الاستبدال
- الـ Firmware (ESPHome) يلتزم هذا المبدأ

**للموقع:** الوصول للـ IoT devices عبر Supabase + APIs حصراً — لا اتصال مباشر بـ Pi
